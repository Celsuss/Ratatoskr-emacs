* Ratatoskr Emacs

A modular, Evil-based Emacs configuration built for speed and productivity.

** Features

- *Evil mode* with full Spacemacs-style =SPC= leader keybindings via =general.el=
- *Elpaca* package manager with lockfile support for reproducible builds
- *Modular architecture* — each concern lives in its own =lisp/init-*.el= file
- *Completion stack* — orderless + vertico + marginalia + consult + embark
- *LSP support* with =lsp-mode=, =lsp-ui=, =breadcrumb= header context, and =corfu= completion
- *Apheleia* format-on-save (lsp formatting disabled — apheleia owns all formatting)
- *Language support* — Python, Rust, Go, C++, CMake, Terraform, YAML, Ansible, Helm templates, Dockerfile, Markdown, Just, PKGBUILDs, Jupyter notebooks
- *Godot 4.x / GDExtension* game development (clangd, dap-lldb, CMake)
- *Org-mode* — org-roam, org-super-agenda, org-kanban, org-download, org-transclusion, ox-hugo (blog export), org-re-reveal (reveal.js slides)
- *Kubernetes* — kubel integration for cluster management
- *Git* — magit, diff-hl (gutter indicators), browse-at-remote
- *LLM tools* — gptel, ellama, aidermacs (Ollama), agent-shell
- *Snippets* — yasnippet with 63 custom snippets across 9 modes
- *Multiple cursors* via =evil-mc=
- *REST client* — restclient for =.http= files
- *Workspaces* via =persp-mode=
- *Dashboard* start page with agenda, org-roam stats, and git status
- *Resilient startup* — modules load inside =condition-case=; one broken module won't take down the rest

*** Reveal.js presentations

Slide export runs through =org-re-reveal= (=SPC o p=). reveal.js assets load
from a CDN by default, so no local install is needed while online.

Decks are ordinary org-roam nodes living in the flat roam root
(=rata-reveal-deck-dir=), so they get IDs, show up in =org-roam-node-find=, and
can link to the notes they synthesise. A deck is identified by its
=#+filetags: :presentation:= tag (=rata-reveal-deck-tag=), not by its location —
=SPC o p P= exports every tagged note by querying the roam DB, the same
technique =init-org.el= uses for =:hastodo:= agenda inclusion.

Exported HTML goes to =~/workspace/second-brain/presentations/=
(=rata-reveal-export-dir=), outside =org-roam-directory=, so generated files never
enter the note tree — the same split as =hugo/= vs =hugo/public/=.

To start a new deck, use the =presentation= org-roam capture template
(=SPC o r c= then =r=, or =SPC o p n=). To turn a note you already have into a
deck, open it and press =SPC o p a= — it adds the tag and the =#+REVEAL_*=
keywords in place, leaving your content alone.

To present offline, run =SPC o p i= once — it shallow-clones reveal.js to
=~/.local/share/reveal.js= — then =SPC o p r= to point exports at that copy.
=SPC o p v= serves the deck over =simple-httpd= on localhost, which speaker
notes need (they do not work over =file://=).

*** Installing

On Arch Linux everything above is installed by:

#+begin_src sh
  just install-deps
#+end_src

On Debian/Ubuntu, install the core and native-build dependencies with:

#+begin_src sh
  sudo apt install build-essential pkg-config enchant-2 libenchant-2-dev \
      hunspell-en-us cmake libtool-bin ripgrep fd-find
#+end_src

Language servers and formatters on non-Arch systems come from their own
ecosystems (=npm=, =pip=, =go install=, =rustup=) — install the ones you need for
the languages you use.

** Getting Started

*** Clone

#+begin_src sh
  git clone https://github.com/Celsuss/Ratatoskr-emacs.git ~/workspace/Ratatoskr-emacs
#+end_src

*** Run

#+begin_src sh
  just run
#+end_src

Or manually:

#+begin_src sh
  emacs --init-directory ~/workspace/Ratatoskr-emacs
#+end_src

The justfile auto-detects the Emacs binary (=/usr/bin/emacs=, snap, or PATH);
set =EMACS_BIN= to override it per machine.

*** First Run

On the first launch Elpaca will clone and build all packages — this takes a few minutes. Subsequent startups are fast.

To install icon fonts and tree-sitter grammars:

#+begin_src sh
  just install-fonts
  just install-grammars
#+end_src

** Reliability (ARE)

This config carries an [[file:.are/INDEX.md][Autonomous Reliability Engineering]] layer: a small knowledge base,
a failure log, risk rules, and three bash scripts that compose the =just= targets above
into risk-based verification levels. It adds no dependency and duplicates nothing —
=AGENTS.md= still owns conventions, the =justfile= still owns commands, and =tests/=
still owns the truth.

Start at =.are/INDEX.md=. Before changing a module, run =just are-context "what you are
doing"=; it prints the risk tier and the exact knowledge worth reading. Verification
levels, and what each one does *not* prove, are in =.are/knowledge/TESTING_STRATEGY.md=.

#+begin_src sh
  just are-verify fast       # ~4s   — lint + claude-loop e2e + audit, no packages needed
  just are-verify relevant   # ~2min — adds byte-compile + the ERT suite
  just are-verify full       # ~3min — adds batch startup; what the pre-commit hook runs
#+end_src

Note: the pre-commit hook is not active until you run =just install-hooks=, and there is
no CI. See =.are/memory/FAILURE_INDEX.md=.

** Claude Code Task Loop

Work a checklist file top to bottom with Claude Code, one task per run.

Write the tasks in any =.md= or =.org= file:

#+begin_src markdown
- [ ] Implement the database schema for the user profiles
- [ ] Write unit tests for the schema validation
- [ ] Update the API documentation
#+end_src

Open that file and hit =SPC a i c l l=. Each task is handed to its own
=claude -p= process, so every task starts from a *clean context* — no
=/clear= needed, and nothing leaks between tasks. Org =TODO= headings work
too and are moved to =DONE=.

Claude runs in the repository containing the task file — the nearest
directory above it holding a =.git= (or another marker in
=rata-claude-loop-root-markers=). If there is no repository, it runs in the
task file's own directory. A marker sitting in =$HOME= is deliberately
ignored, so a dotfiles repo or a stray =~/package.json= cannot turn your
entire home directory into the working directory. =C-u C-u SPC a i c l l=
prompts for the directory if you need to override it.

Progress is rendered into =*claude-loop*=; the child runs with
=--output-format stream-json= and its events are decoded into readable prose
and tool calls rather than raw JSON.

*** When is a task "done"?

Not when =claude -p= exits 0. It exits 0 whenever the *CLI* succeeded, which
includes a task that looked at the problem and gave up, and a task whose
every edit was silently denied — print mode denies instead of prompting. A
box is ticked only when all of these hold:

- the process exited 0, and the final =result= event reports subtype
  =success= with no error;
- no tool in =rata-claude-loop-critical-denial-tools= (=Edit=, =Write=,
  =MultiEdit=, =NotebookEdit=) was denied — a denied =WebFetch= is reported
  but tolerated, since halting a good run over it would be worse;
- the task did not report =RATA-TASK-STATUS: blocked=. Every prompt asks for
  a status line as its last line, which is how a task says "I could not do
  this" in a way the loop can act on;
- =rata-claude-loop-verify-command=, if set, exited 0.

The box is also only ticked on a line that *still holds that task*. The text
is matched, not just the line number, so a checklist that shifted while a
half-hour task ran cannot get the wrong box ticked; an ambiguous or missing
task halts and says so instead.

*** Verification and retry

=rata-claude-loop-verify-command= is the strongest gate available, and it now
runs asynchronously — Emacs stays responsive through your test suite. Set it
globally or per project via =.dir-locals.el= (it is deliberately *not* a
=safe-local-variable=: it is a shell command, so Emacs should ask).

When an attempt fails, the loop does not throw the work away. It captures the
=session_id= from the run and retries with =claude -p --resume=, handing back
the reason and the tail of the failing output — so the second attempt already
knows what it did and what broke, rather than starting from a clean context.
=rata-claude-loop-max-attempts= (default 2, i.e. one retry) bounds it, and
=rata-claude-loop-retry-on= chooses which failures are worth retrying. A
timeout and a self-reported =blocked= are excluded on purpose: the first
leaves unknown partial state, the second is a considered judgement.

If the retry does not help, =SPC a i c l o= opens a vterm running =claude
--resume= on that same session, so you can take over by hand from exactly
where it got stuck.

*** Keys

| Key           | Action                     |
|---------------+----------------------------|
| =SPC a i c l l= | Start the loop             |
| =C-u SPC a i c l l= | Start, prompting for the task file |
| =C-u C-u SPC a i c l l= | ...and for the working directory |
| =SPC a i c l r= | Run only the task at point |
| =SPC a i c l s= | Stop (SIGINT, then SIGKILL after a grace period) |
| =SPC a i c l n= | Skip current task (=[-]=)    |
| =SPC a i c l c= | Resume after a halt        |
| =SPC a i c l t= | Retry the current task by resuming its session |
| =SPC a i c l o= | Take over the session in a vterm |
| =SPC a i c l b= | Show the output buffer     |
| =SPC a i c l ?= | Status                     |

In the =*claude-loop*= buffer itself: =q= quits, =gr= reports status, =gt=
retries, =go= takes over, =C-c C-k= stops.

*** Settings worth reviewing

#+begin_src elisp
;; The strongest quality gate. Runs asynchronously, so a long suite does not
;; freeze Emacs.
(setq rata-claude-loop-verify-command "just test")

;; How much autonomy each run gets. In print mode there are no interactive
;; permission prompts -- anything not permitted is silently denied.
(setq rata-claude-loop-extra-args '("--permission-mode" "acceptEdits"))

;; Guard rails. There is no CLI timeout flag, so that timer lives in Emacs.
(setq rata-claude-loop-task-timeout 1800)   ; seconds per attempt
(setq rata-claude-loop-max-turns 60)        ; --max-turns
(setq rata-claude-loop-task-budget-usd 2.0) ; --max-budget-usd per attempt
(setq rata-claude-loop-fallback-model "sonnet") ; survive an overload

;; Print a per-task `git diff --stat' into the loop buffer. Read-only: nothing
;; is committed, stashed or reset.
(setq rata-claude-loop-git-checkpoint 'record)
#+end_src

See =M-x customize-group RET rata-claude-loop= for the rest.

*** Testing it

The pure parts (task scanning, checkbox marking, stream decoding, outcome
classification, argv building) are covered by ERT in =tests/run-tests.el=.
The state machine itself — spawn, async verify, retry-by-resume, timeout,
marking — is driven against a stub CLI by =just test-claude-loop=, which
makes no API calls and spends nothing.

** Adding a New Module

1. Create =lisp/init-{name}.el= with =;;; -*- lexical-binding: t; -*-= header
2. Use =use-package= for all packages (=:ensure t= is the default)
3. End the file with =(provide 'init-{name})=
4. Add =(rata-load-module 'init-{name})= to =init.el=
