# FAIL-0005 — the pre-commit gate exists but is not installed

| | |
|---|---|
| **Date found** | 2026-08-19 (ARE bootstrap) |
| **Severity** | MEDIUM |
| **Category** | verification-gap, configuration |
| **Area** | `.githooks/pre-commit`, git config |
| **Origin** | pre-existing |
| **Status** | OPEN — one operator command away |

## Symptoms

```
$ git config --get core.hooksPath
(empty)
```

`.githooks/pre-commit` exists and runs the test suite. `just install-hooks` exists and sets
`core.hooksPath`. Neither has been run in this checkout, so git is still using
`.git/hooks/`, which contains only the stock samples.

**There is no CI in this repository** — no `.github/`, no `.gitlab-ci.yml`, verified absent.
The pre-commit hook is therefore the *only* automated gate that could exist, and it is off.
Every commit in this repo has been made without any check running.

## Root cause

`core.hooksPath` is per-clone local configuration; it is not carried by a clone and cannot
be committed. So a repo that ships hooks in `.githooks/` **always** starts with them
disabled, in every checkout, forever, until someone runs the install step by hand. Both
checkouts on this machine are in that state.

Repos with CI do not notice, because CI catches what the hook would have. This one has no CI.

## Why it escaped detection

Nothing reports the gate's own status. `just test` passing tells you the tests are fine; it
says nothing about whether anything runs them when it matters. The `README.org` command
table lists `just install-hooks` as "one-time setup", which reads as done rather than
pending.

## Impact

Bounded but real: the operator can commit a config that fails `just test`. Given that this
repository *is* the editor, a bad commit that reaches the other checkout or another machine
costs a broken editor at the next start. `rata-load-module` limits the damage to one module
rather than total failure.

## Fix

**Not applied.** Running `git config core.hooksPath .githooks` changes the operator's local
commit workflow — every commit would then take ~3 minutes. That is a workflow decision, not
a defect fix, and it is theirs.

Recommended:

```sh
just install-hooks
```

The hook now runs `just are-verify full` (see [FAIL-0004](FAIL-0004.md)), so installing it
gates lint, compile, startup, ERT, the claude-loop e2e suite and the ARE audit.

If ~3 minutes per commit is too slow to accept, the useful compromise is a hook that runs
`just are-verify fast` (~4 s) and leaves `full` to be run deliberately before pushing.

## Regression protection

`scripts/are-audit.sh` check `hooks-installed`: warns (does not fail) when
`core.hooksPath` is not `.githooks`. A warning rather than a failure on purpose — a
checkout that has not been set up is not broken, and failing the audit would make the audit
unusable on a fresh clone. The session-start hook surfaces the warning at the top of every
session, which is where it will actually get acted on.

## Verification improvement

Generalised as L-005 in [../LESSONS.md](../LESSONS.md) — *a gate that requires manual
enablement is off by default; verify the gate, not just the tests.*
