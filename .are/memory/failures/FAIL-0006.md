# FAIL-0006 — a module could be added to `lisp/` and never wired into `init.el`

| | |
|---|---|
| **Date found** | 2026-08-19 (ARE bootstrap) |
| **Severity** | LOW |
| **Category** | verification-gap |
| **Area** | `init.el`, `lisp/`, `tests/run-tests.el` |
| **Origin** | pre-existing (latent — no live instance) |
| **Status** | FIXED with a regression test |

## Symptoms

None observed. This is a gap found by inspection, not a failure that occurred.

Audited at bootstrap: 36 files match `lisp/init-*.el`; 35 have an active
`(rata-load-module 'init-…)` line in `init.el`. The single unloaded module is
`lisp/init-mcp.el`, whose load line is commented out on purpose
(`;; (rata-load-module 'init-mcp)  ; experimental — uncomment when stable`). There is no
accidental orphan today.

## Root cause of the gap

Adding a module is a four-step manual procedure documented in `AGENTS.md`
(create the file, follow the `use-package` pattern, add `(provide …)`, add the
`rata-load-module` line). Steps 1–3 are enforced by `scripts/lint.sh`
(lexical-binding header, `provide` matching the filename). **Step 4 is enforced by
nothing.**

A module that is created but never wired in loads no packages, binds no keys and signals no
error. It is invisible. It also passes every existing check:

- `lint.sh` iterates `lisp/init-*.el` and is happy with the file itself;
- `just compile` compiles it standalone and is happy;
- `just batch` never requires it;
- `rata-test-no-failed-modules` only inspects modules that *were* required;
- the keybinding tests read binding forms from the file **statically**, so they would even
  validate the keybindings of a module that never loads — arguably making the orphan look
  *more* healthy than it is.

The inverse also had no check: a `rata-load-module` line for a file that has been renamed or
deleted. That one at least surfaces loudly in `*init-errors*` at startup, but only when
somebody starts Emacs interactively — never in batch.

## Fix

Applied: `rata-test-init-loads-every-module` in `tests/run-tests.el`, asserting both
directions.

- Every `lisp/init-*.el` must have an active (non-commented) `(rata-load-module 'NAME)` line
  in `init.el`, **or** appear in `rata-test--excluded-modules`.
- Every `rata-load-module` line in `init.el` must have a corresponding file in `lisp/`.

It reuses the existing `rata-test--excluded-modules` list (currently `("init-mcp.el")`)
rather than introducing a second list of known-unloaded modules — that variable already
served exactly this purpose for the keybinding tests, so there is still one source of truth.

Anchoring matters: the check must match `^(rata-load-module 'NAME)` at the start of a line,
or a commented-out load line counts as loaded. That mistake was made and caught while
writing this check — a naive substring match reported zero orphans including `init-mcp`.

The ERT test above. Recorded as invariant I7 in

## Verification improvement

Generalised as L-006 in [../LESSONS.md](../LESSONS.md) — *when a procedure has N steps and
the linter enforces N-1, the unenforced step is the one that silently rots.*
