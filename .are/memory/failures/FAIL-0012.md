# FAIL-0012 — `eval-when-compile (require 'org)` is a load-time require, so init pulled built-in Org before elpaca

| | |
|---|---|
| **Date found** | 2026-08-27 |
| **Severity** | MEDIUM |
| **Category** | configuration, verification-gap, self-inflicted |
| **Area** | `lisp/init-dialogic.el`, `scripts/are-verify.sh`, `justfile` `batch` |
| **Origin** | introduced by `a488d5c` (the dialogic module, same day) |
| **Status** | FIXED — requires replaced by `defvar` / `declare-function`; `just batch-strict` now reads the startup output, not only the exit code |

## Symptoms

Reported by the operator on the first interactive start after `a488d5c`:

```
⛔ Warning (emacs): org loaded before Elpaca activation
⛔ Warning (emacs): Org version mismatch.  (×4)
```

Nothing failed. Emacs started, every module loaded, and `just are-verify full` had reported
PASS on all seven steps immediately before the commit — including `batch-startup`.

## Mechanism

`lisp/init-dialogic.el` opened with what AGENTS.md recommends for compile-time dependencies:

```elisp
(eval-when-compile
  (require 'org)
  (require 'org-element)
  (require 'ox))
```

`eval-when-compile` evaluates its body at compile time **and, in interpreted code, is
equivalent to `progn`** (Emacs Lisp manual, "Eval During Compile"). No `.elc` is committed
for `lisp/`, and `rata-load-module` loads the source, so that form is simply
`(require 'org)` executed while `init.el` is still loading modules.

That is early enough to matter. `init-pkg.el` bootstraps elpaca, but elpaca *activates* its
built packages later; a `require` before that point resolves against the Org that ships
inside Emacs (9.7.11). Every later org package — org-roam, ox-hugo, org-super-agenda — then
loads against a different Org than the one on elpaca's load-path and warns about the
mismatch. Confirmed in isolation:

```sh
emacs -Q --batch --eval '(progn (add-to-list (quote load-path) (expand-file-name "lisp"))
  (load (expand-file-name "lisp/init-dialogic.el"))
  (message "org=%S %s" (featurep (quote org)) (org-version)))'
# => org=t 9.7.11        (before the fix)
# => org=nil             (after)
```

`init-present.el` had the pattern right all along and was the model for the fix: its
`eval-when-compile` block contains only `cl-lib` (built-in, already loaded, harmless) plus
`defvar` stubs, with `declare-function` for the rest.

## Why the gate said PASS

`scripts/are-verify.sh` judges every step by **exit code**, and `just batch` exits 0 whether
or not init filled the warning buffer. The Org mismatch text was in fact printed in the
middle of the `are-verify full` output that ran seconds before the commit, and in the
pre-commit hook's output too — a human reading either would have seen it scroll past. The
step's own scope line said "init runs to completion", which was true and useless: nothing
asserted anything about *how* it completed.

This is the FAIL-0003 shape again — a check whose name reaches further than its assertion.

## Fix

1. `lisp/init-dialogic.el` requires nothing at load time. Symbols are declared:
   `defvar` for the three org variables it touches, `declare-function` for the fourteen
   functions. Byte-compilation is down to one warning (`rata-leader`), the same benign one
   `init-present.el` produces.
2. New `scripts/check-startup.sh` / `just batch-strict`: runs `just batch`, prints the
   output, and **fails on the class of warning** rather than this instance —
   `"loaded before Elpaca activation"` (elpaca emits it for any package required too early)
   and `"Org version mismatch"`. `are-verify full` now runs `batch-strict`.
3. Verified in both directions: green on the fixed tree, and exit 1 with
   `check-startup: FAIL — startup emitted: Org version mismatch` when the `(require 'org)`
   is put back.

## Regression protection

`just batch-strict`, in `are-verify full` and therefore in the pre-commit hook.

## Lessons

- L-028 — `eval-when-compile` is `progn` when interpreted, so it is not a place to hide a
  `require` in a config loaded from source.
- L-003 / FAIL-0003 — a step judged by exit code proves only that nothing signalled.
