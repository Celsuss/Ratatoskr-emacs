# FAIL-0008 — the ARE audit's first run produced three false results

| | |
|---|---|
| **Date found** | 2026-08-19 (ARE bootstrap) |
| **Severity** | LOW |
| **Category** | verification-gap, self-inflicted |
| **Area** | `scripts/are-audit.sh`, `scripts/are-context.sh` |
| **Origin** | **introduced by ARE** |
| **Status** | FIXED |

Recorded because the bootstrap report distinguishes pre-existing problems from ones ARE
introduced, and these are the ones ARE introduced. All three were caught by running the new
tooling before trusting it, and all three were fixed in the same session.

## What happened

The first execution of `scripts/are-audit.sh` reported 3 errors and 6 warnings. Two of the
errors and one warning were bugs in the checks, not in the repository.

### 1. `are-files-committable` — false FAIL on `.claude/settings.local.json`

The check asserts that every file ARE creates can reach version control. It flagged
`.claude/settings.local.json`, ignored by the user's global gitignore at
`~/.config/git/ignore`.

**Root cause:** the check's premise was "an ignored ARE-adjacent file is a bug", but
`*.local.*` files are per-checkout config that is *supposed* to be ignored. The check
confused "ARE created this" with "everything in these directories".
**Fix:** skip `*.local.json` / `*.local.yaml` / `*.local.yml`.

### 2. `gate-covers-tests` — false FAIL on both test targets

The check asserts every `test-*` target in the `justfile` is reachable from a gate. It
grepped the `are-verify` *recipe body* in the `justfile` for each target name — and that
body is a single line, `./scripts/are-verify.sh {{level}}`. The steps live in the script.
So the check could only ever fail.

**Root cause:** the check was pointed at the artifact that *names* the work rather than the
one that *does* it. Delegation moved the evidence and the check did not follow.
**Fix:** grep `scripts/are-verify.sh` for `just <target>` instead.
Generalised as [L-010](../LESSONS.md).

### 3. `docs-paths` — duplicate warning from markup

`AGENTS.md` was reported twice for the same path, because one occurrence is written
`` `--init-directory ~/workspace/Ratatoskr-emacs` `` and the trailing backtick survived
extraction, so `sort -u` saw two distinct strings.
**Fix:** strip trailing markup and punctuation before deduplicating.

### 4. `are-context.sh` — mangled area list (found separately)

`**Affected areas:** are,autonomous-agent conventions,docs editing,historical` — commas and
spaces alternating. `paste -sd', '` treats `", "` as a **cycling list of delimiters**, not a
two-character separator, so it alternated `,` and ` ` between items.
**Fix:** `paste -sd',' -` then `sed 's/,/, /g'`.

## Why it matters

Three of these four are the same failure in different clothes: **a check that cannot
distinguish its true case from its false case is worse than no check**, because it is read
as authoritative. The `gate-covers-tests` bug is the sharpest — it *always* failed, which is
at least loud. A check that always *passes* would have been invisible, and that is the shape
to fear.

## Regression protection

The tooling was exercised adversarially before being trusted: each audit check was
deliberately broken and confirmed to fire, then restored.

| Check | Break injected | Result |
|---|---|---|
| `no-auto-approve` | added `(compile "terraform apply -auto-approve")` to `init-terraform.el` | FAIL, correct line reported |
| `map-covers-modules` | created an unmapped `lisp/init-aretmp.el` | FAIL, named the file |
| `gate-covers-tests` | replaced `just test-claude-loop` in the driver with `echo skipped` | FAIL, named the target |
| `failure-index-complete` | deleted the FAIL-0007 row from the index | FAIL, named the record |

All four fired; all four were restored; the audit returned to its 0-error baseline.

## Verification improvement

Proving a check can fail is now part of adding one — see [L-008](../LESSONS.md) and
`.are/rules/VERIFICATION_RULES.md` §4.
