# FAIL-0004 — the CRITICAL module's e2e suite sits outside `just test`

| | |
|---|---|
| **Date found** | 2026-08-19 (ARE bootstrap) |
| **Severity** | MEDIUM |
| **Category** | verification-gap |
| **Area** | `justfile` (`test`, `test-claude-loop`), `.githooks/pre-commit` |
| **Origin** | pre-existing |
| **Status** | FIXED via the ARE gate |

## Symptoms

`just test` is `lint compile batch test-ert`. `just test-claude-loop` is a separate target
that nothing depends on. The `justfile` says why:

```
# Runs real processes and timers, so it is kept out of `test'.
```

`.githooks/pre-commit` runs `just test`. Therefore the pre-commit gate does not exercise
`lisp/init-claude-loop.el`'s state machine — 1573 lines, the largest module in the repo, the
only one with a state machine, and the only area classified CRITICAL
([../../knowledge/MODULES.md](../../knowledge/MODULES.md)).

## Root cause

The exclusion was a reasonable judgement when written: an e2e suite that spawns processes
and arms timers looks like something that will be slow and flaky in a gate.

Measured, it is neither. `just test-claude-loop` runs under `emacs -Q` against a stub CLI
written by the suite itself, contacts no network, and completes in **3.0 s** — faster than
`just compile` (24 s), `just batch` (70 s) and `just test-ert` (78 s), each of which *is* in
the gate. It also needs no packages installed, so it is the cheapest meaningful check the
repo has.

The stated reason ("real processes and timers") is accurate about the mechanism and wrong
about the consequence.

## Why it escaped detection

Nothing audits which tests are wired into which gate. Both targets exist, both pass, and
the `justfile` comment makes the omission look deliberate and settled — so nobody
re-measured it.

## Fix

Applied, without changing the meaning of the existing target:

- `just test` is left exactly as it was, so existing habits and docs stay correct.
- `just are-verify fast` includes `test-claude-loop` — so the CRITICAL area is covered by
  the *cheapest* level, and by the session-start hook.
- `just are-verify full` = `just test` + `test-claude-loop` + `just are-audit`.
- `.githooks/pre-commit` now runs `just are-verify full` instead of `just test`, so the gate
  covers everything. Cost: +4 s on a ~2.9 min hook.

## Regression protection

`scripts/are-audit.sh` check `gate-covers-tests`: enumerates `test-*` recipes in the
`justfile` and fails if any of them is not reachable from `are-verify full`. Adding a new
test target without wiring it into a gate now fails the audit.

## Verification improvement

The inversion is deliberate and recorded: the fast level covers the critical area, because
cost and criticality are independent. Generalised as L-004 in [../LESSONS.md](../LESSONS.md).
