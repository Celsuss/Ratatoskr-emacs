# FAIL-0026 — 19 ERT failures on `dev` @ 5a36a4e, not caused by the session that found them

- **Severity:** MEDIUM (`just are-verify relevant` red; masks any new failure in those areas)
- **Class:** verification-gap
- **Found:** 2026-10-11, while verifying the org-roam `n` fix. Confirmed pre-existing by
  `git stash` + `just test-ert`: 210 tests, 19 unexpected, before the change; 211 / 19 after.
- **Symptom:** 18 `rata-test-hn-*` tests fail (`rata-test-hn--requests` stays nil,
  `(wrong-type-argument stringp nil)` in `rata-test-hn-article-failures-degrade`), and
  `rata-test-keybindings-all-commandp` fails on `SPC a i a o` → `aidermacs-open` "is not a
  command" (`init-llm.el`).
- **Cause (aider):** upstream aidermacs no longer has `aidermacs-open`; `aidermacs-run` is
  its replacement. Fixed 2026-10-11: `SPC a i a o` now binds `aidermacs-run`, and
  `rata-test-keybindings-all-commandp` passes again — it is the check that caught it.
- **Cause (HN):** elfeed upstream moved development from `master` to `main`; `master` is
  frozen at bbb3cac (2026-02-18). Both checkouts' elpaca clones were made while `master`
  was the default and still track it, and elpaca never re-reads a remote's default branch.
  `elfeed-show-update-hook` (and `elfeed-show-auto-readable` / `-auto-fetch-link`) exist
  only on `main` (4.2.x, 2026-09), which `init-elfeed-hn.el` was written against. On
  `master` nothing runs the hook, so the `add-hook` binds a variable no one reads: every
  test through `elfeed-show-entry` fails, and **the live HN view silently does nothing**.
  The `stringp nil` error is the same thing seen from `rata-test-hn-article-failures-degrade`.
- **Why not caught:** CI (`.github/workflows/ci.yml`) runs lint, compile, claude-loop
  and audit, not ERT; a fresh clone there would get `main` anyway. Locally the
  tests were red, but nothing recorded it until 2026-10-11.
- **Fix (in git):** `:ensure (elfeed :branch "main")` in `init-elfeed.el`; `init-elfeed-hn.el`
  raises a `display-warning` when `elfeed-show-update-hook` is unbound instead of creating
  it. That also turns `rata-test-hn-non-hn-entry-untouched` red on a stale elfeed: it had
  passed vacuously, comparing two renders neither of which ran the hook.
- **Fix (per machine, operator):** an existing clone keeps its branch. In each checkout:
  `git -C elpaca/sources/elfeed checkout -B main origin/main`, `M-x elpaca-rebuild RET
  elfeed`, restart.
- **Status:** FIXED 2026-10-11. The operator switched this checkout's clone to `main`
  (4c962a4) and rebuilt; `just are-verify relevant` then passed with 211/211 ERT. Any other
  checkout's clone (e.g. `~/.config/emacs`, FAIL-0001) needs the same switch, and the
  `rata-elfeed-hn` warning says so at load.
