# FAIL-0007 — stray untracked file at the repository root

| | |
|---|---|
| **Date found** | 2026-08-19 (ARE bootstrap) |
| **Severity** | LOW |
| **Category** | repo-hygiene |
| **Area** | repository root |
| **Origin** | pre-existing |
| **Status** | FIXED — deleted 2026-08-24 on operator instruction; the `stray-files` check stays |

## Symptoms

`git status` reports an untracked file at the repository root whose name is a single
character, `ɢ` (U+0262 LATIN LETTER SMALL CAPITAL G — git renders it escaped as
`"\311\242"`):

```
?? "\311\242"
```

Contents: `boom\n`. 5 bytes, ASCII, mtime 2026-08-19 12:06.

## Investigation

`boom` appears in the test tree in two places — `tests/run-tests.el:409` and
`tests/claude-loop-e2e.el:226`, the latter as the stub verify command
`echo 'boom'; exit 3`. That makes a test artifact the obvious suspect, so it was checked
directly: `just test-claude-loop` was run and the file's mtime did **not** change, and the
suite writes only into a `make-temp-file` directory. The e2e suite is not the source.

The remaining explanation is a shell typo — a redirection into a mistyped target while
someone was working on that verify command by hand. Not proven, and not worth more effort
than that: whatever created it, it is not produced by any code in this repository.

## Why it matters

Very little on its own, and it is worth being clear about that. It is one 5-byte file. The
reason to record it at all:

- `git add .` or `git add -A` would commit it, and a file with a non-ASCII single-character
  name is unpleasant to notice and remove later, especially on a public remote.
- More usefully, it revealed that **nothing in this repository notices unexpected untracked
  files.** `no-littering` and `.gitignore` cover *generated* clutter thoroughly; neither
  covers accidental clutter.

## Fix

**Deleted 2026-08-24**, after the operator was shown the contents (`boom`, 5 bytes) and
asked for its removal:

```sh
rm -- ./ɢ
```

It stayed for five days before that, and deliberately. It was an untracked file the
operator created, outside anything ARE had been asked to change, and deleting someone's
file to tidy a report is the wrong trade even when the file says `boom` — the report was
the correct output, and the deletion was the operator's call to make. Recorded here
because the *delay* was the right behaviour, not an oversight to avoid repeating.

The check that found it is unchanged: the next stray file gets reported the same way and
also waits for an instruction.

## Regression protection

`scripts/are-audit.sh` check `stray-files`: lists untracked paths at the repository root
whose extension is not one of `el md org sh yaml yml json png` and whose name is not a known
directory, as a **warning**. Warning rather than failure — work-in-progress files are normal
and an audit that cries wolf gets ignored. The session-start hook surfaces it, which is
enough for a hygiene item.

## Verification improvement

Generalised as L-007 in [../LESSONS.md](../LESSONS.md) — *`.gitignore` protects against
clutter you predicted; nothing protects against clutter you did not.*
