#+title: jira.el cheat sheet (Ratatoskr-emacs)
#+options: toc:2 num:nil

Keys as they resolve *in this config*, measured in a live buffer — not as jira.el's readme
lists them. Two layers make up what you press:

- **evil stays live in the Jira buffers** (D-015): normal state, so ~j~/~k~, ~/~, ~q~ and the
  ~SPC~ leader work as everywhere else, and evil-collection supplies the tablist half
  (marking, filtering, sorting, refresh).
- **jira.el's own keys sit under the local leader ~,~**, because evil's normal state shadows
  the single-letter keys of a =tabulated-list-mode= / =magit-section-mode= child (L-017). The
  mirror is built by ~lookup-key~ out of jira.el's own maps, so it carries no upstream
  internals; ~rata-jira-*-key-mirror~ in the config is the source of truth for the table
  below, and =rata-test-jira-mirrored-keys-exist-upstream= fails if upstream renames one.

Inside a transient (the ~?~ and ~l~ popups) upstream's own letters apply unchanged: transient
takes over the keyboard, so evil is not in the way there.

* Getting in

| Key     | Command      | Does                                        |
|---------+--------------+---------------------------------------------|
| ~SPC J j~ | =jira-issues= | Open the issue list (=*Jira Issues*=)        |
| ~SPC J t~ | =jira-tempo=  | Open Tempo worklogs (=*Jira Tempo*=)         |

Both are the only autoloaded entry points; everything else is reached from inside
those buffers.

* Issue list — =*Jira Issues*= (=jira-issues-mode=)

Actions act on the *marked* issues, falling back to the issue on the current line when
nothing is marked (dired semantics, via tablist).

** Query menu (~, l~) — what it is

~, l~ opens a *transient*: a temporary window at the bottom of the frame listing one letter
per JQL argument, exactly like a magit popup. Inside it, upstream's own keys apply — evil is
not involved. It is a two-stage interaction, and the second stage is the one that is easy to
miss:

1. Press an argument's letter. It prompts (with completion from live instance data) and
   the chosen value is then shown next to that letter in the popup. The popup stays open;
   set as many arguments as you like.
2. Press ~l~ — plain ~l~, inside the popup — to run the query. Nothing is sent to Jira until
   you do.

~C-g~ dismisses the popup. *The arguments are not sticky:* transient re-initialises the
prefix from its default value on every invocation — here =--myself=, the status exclusion
in =--jql== (see below), and =jira-issues-default-type= if set
(=jira-issues--transient-default-value=, plus this config's advice on it) — so a filter you
built by hand is gone the next time you open it. That is what ~C-x s~ (this session) and
~C-x C-s~ (all sessions) are for: they store the current argument set in the prefix itself, and
only then does reopening the menu show what you last ran. ~C-x C-k~ goes back to the default.

** Query menu — the arguments (all pressed inside the popup)

Each argument prompts with completion from live instance data (statuses, projects,
users, versions, types). Set what you want, then press ~l~ to run the query.

| Key     | Argument           | Notes                                          |
|---------+--------------------+------------------------------------------------|
| ~m~       | =--myself=          | Only issues assigned to you (on by default)     |
| ~a~       | =--assignee=        | Inapt while =--myself= is on; ~[EMPTY]~ = unassigned |
| ~c~       | =--current-sprint=  | Only the active sprint                          |
| ~s~       | =--status=          | From the instance's statuses                     |
| ~p~       | =--project=         |                                                 |
| ~t~       | =--type=            | ~Any~ clears it                                   |
| ~R~       | =--reporter=        |                                                 |
| ~r~       | =--resolution=      |                                                 |
| ~v~       | =--version=         | Fix version                                     |
| ~j~       | =--jql=             | Raw JQL — escape hatch. *Pre-filled* with the status exclusion; clear it to see finished issues |
| ~l~       | —                  | *Run the query*                                  |
| ~F~       | —                  | Apply a saved Jira filter (ignores the args above) |
| ~C-x s~   | —                  | Remember these args for this Emacs session       |
| ~C-x C-s~ | —                  | Persist these args across sessions               |

* Issue detail — =*Jira Issue*= (=jira-detail-mode=)

A =magit-section= buffer in evil normal state. Folding and section motion come from
evil-collection and are not re-bound: ~TAB~ folds the section at point, ~M-n~ / ~M-p~ move
between siblings, ~1~–~4~ set the global fold level, ~z a~ / ~z c~ / ~z o~ fold as in vim, ~q~ quits.
~j~ / ~k~ move by line.

| Key | Upstream | Does                                                  |
|-----+----------+-------------------------------------------------------|
| ~, ?~ | ~?~ / ~h~    | *Actions menu* (transient), context-aware              |
| ~, c~ | ~+~        | Add a comment                                          |
| ~, e~ | ~e~        | Edit the comment at point                              |
| ~, x~ | ~-~        | Remove the comment at point                            |
| ~, s~ | ~C~        | Change issue status / resolution / estimate            |
| ~, u~ | ~U~        | Update an arbitrary issue field                        |
| ~, w~ | ~w~        | Watchers submenu — ~+~ add, ~-~ remove                    |
| ~, S~ | ~S~        | Add a subtask (asks for the type if several)            |
| ~, p~ | ~P~        | Show the parent issue                                  |
| ~, o~ | ~O~        | Open in the browser                                    |
| ~, f~ | ~f~        | Find another issue by key or URL                       |
| ~, y~ | ~c~        | Copy the issue key to the clipboard                    |
| ~, r~ | ~g~        | Refresh                                                |
| ~, m~ | —        | *Sprint* prefix — same commands as in the list         |

With point on a subtask or a linked-issue section, the actions menu (~, ?~) grows two
entries: ~RET~ opens it in Emacs, ~o~ opens it in the browser — those are transient keys, so
they are upstream's.

* Sprints — the board is a never-ending sprint

The team board is a Scrum board in Jira with one sprint that is never closed, used as a
kanban board. "Put this on the board" therefore means "move it into the active sprint",
and jira.el has no command for it (it only reads the Sprint field). These are this
config's own commands (=lisp/init-jira.el=, Agile REST API through jira.el's request
layer), available under ~, m~ in both the issue list and the issue detail buffer. They act
on the marked issues, else the one at point.

| Key     | Does                                                                          |
|---------+-------------------------------------------------------------------------------|
| ~, m s~   | Move to a sprint. The *active* sprint is the default and labelled =[active]= — RET takes it |
| ~, m b~   | Move to the backlog, i.e. off the board (asks first)                          |
| ~, m a~   | Say which sprint is active on the board, and when it ends                     |
| ~, m o~   | Choose the board for this session (from the boards the instance lists)        |
| ~, m r~   | Forget cached boards and sprints; the next command fetches them again         |

The sprint prompt reads =Move PROJ-1 to sprint (default Board  [active]  ends 2030-01-01):=
and the confirmation names the sprint it moved to, so a wrong sprint cannot pass for
success. ~C-u~ before ~, m s~ or ~, m a~ refetches the sprint list first.

The board is =rata-jira-board-id= in =local.el= (=rapidView=NNN= in the board URL). Unset,
the first sprint command asks once per session. Errors come back in Jira's own words
(closed sprint, issue outside the board filter, no Jira Software licence).

Tempo needs its own token: a =machine tempo.io= line in =~/.authinfo.gpg=, separate from
the Jira credential.

* Setup this config expects

Credentials are never in the repo. =jira-username= and =jira-token= are deliberately
left unset, which is what makes jira.el fall through to =auth-source=:

#+begin_src authinfo
machine YOUR-INSTANCE.atlassian.net login you@example.com port https password TOKEN
machine tempo.io password TEMPO_TOKEN
#+end_src

The hostname lives in the gitignored =local.el= (it is corporate identity on a public
remote) — see =local.el.example=:

#+begin_src elisp
(setq rata-jira-base-url "https://your-instance.atlassian.net") ; no trailing slash
(setq rata-jira-api-version 3)          ; 2 for older on-premise
(setq jira-token-is-personal-access-token nil) ; t for an on-prem PAT
#+end_src

A trailing slash on the URL silently breaks auth: jira.el derives the auth-source host
by stripping only ="https://"=, so the =machine= line never matches and the request 401s
as though the token were wrong. =init-jira.el= runs the value through
=directory-file-name= to defend against this.

* Things worth knowing

- *Nothing here writes into org-roam.* This is a second view onto work, not a sync
  (D-011). ~, e~ → Org-mode in the issue list is the one-off bridge when you want the
  rows as text.
- *The two transients are the documentation.* ~, ?~ in any Jira buffer and ~, l~ in the issue
  list list every available action with its key; nothing needs to be memorised. Inside them,
  upstream's letters apply.
- *`,` is the local leader, `SPC` is the global one*, and both work here because these
  buffers are in evil normal state. ~which-key~ after ~,~ is the fastest way back into this
  document.
- *Two keys read oddly if you know vim*: ~s~ hides the lines at point (evil-collection maps it
  to =tablist-do-kill-lines=, not =evil-substitute=), and ~S~ sorts. Both are evil-collection's
  choices, shared with every other tablist buffer.
- *The design changed twice, on purpose.* Until 2026-09-08 these buffers were put in *emacs
  state* — and even that never took effect, because the `evil-set-initial-state` call sat in
  the =use-package jira= =:config= block, which never runs: the feature =jira= is never
  loaded here (elpaca autoloads ~jira-issues~ from =jira-issues.el=, and nothing requires the
  =jira= umbrella). So every documented key was dead — ~l~ moved the cursor right, ~?~ searched
  backwards, ~c C I O p~ resolved to ~ignore~. The dead-`:config` bug is
  [[file:../.are/memory/failures/FAIL-0016.md][FAIL-0016]] / L-039; the choice to keep evil
  and mirror the keys instead of switching to emacs state is D-015. Covered by
  =rata-test-jira-buffers-keep-evil-and-mirror-keys= and
  =rata-test-jira-mirrored-keys-exist-upstream=.

* Truncation: the list is one page, and the page is all you get

On this instance =rata-jira-api-version= is 2, i.e. Jira Server/DC.  jira.el
tries the =search/jql= endpoint first and falls back to the legacy =search= one
on a 404 (=jira-api.el:238=), which is what Server/DC returns — =search/jql= is
Cloud-only.

The legacy endpoint paginates with =startAt= and reports =total=.  jira.el reads
neither: it only looks for =nextPageToken= in the response (=jira-issues.el:179=)
and only ever sends one (=jira-issues.el:107=).  Consequences here:

- ~M-n~ always answers "No more pages."  There is no second page to reach.
- The row count is never compared against =total=, so a truncated list looks
  exactly like a complete one.
- The default query is =assignee = currentUser()= with *no* =ORDER BY=, so the
  rows you get are an arbitrary subset, not "the newest" or "the open ones".
  The ~s~ sort only reorders what already arrived.

Mitigations, in order of effort:

1. =jira-issues-max-results= is set to 100 in =lisp/init-jira.el=.  Raise it
   further if you routinely have more than that assigned; the server-side cap
   is =jira.search.views.default.max= (1000 by default).
2. Narrow the query instead of paging it: ~, l~ then ~c~ (current sprint) or ~s~
   (status), or ~j~ for a JQL with an explicit ~ORDER BY~ so the truncation at
   least cuts off the end you care least about.
3. ~F~ applies a saved Jira filter, which is also subject to the same cap.

Note that ~m~ (=--myself=) is on by default, so issues where you are only the
reporter or a watcher never appear at all — that is scope, not truncation.
Turn it off with ~, l~ then ~m~, and set ~R~ (reporter) instead.

The same goes for finished work: =rata-jira-excluded-statuses= (=lisp/init-jira.el=,
default =CLOSED=, =DEPLOYED=, =DONE=, =REJECTED=) is injected as
=status not in (...)= in the =--jql== argument, so the default list is open work only.
Clear ~j~ in the query menu for a one-off look at everything, or trim the variable in
=local.el=. A status name that no status in the instance carries makes Jira reject the
*whole* query with a 400 — an empty list rather than an unfiltered one is the symptom.
